## 2. EXT-AUTO-APPLY：自动网申

### 产品边界

复用 Vocatrya 已有职业资料，减少在各家招聘网站重复录入。用户选择本次使用的资料/简历内容，浏览器扩展识别字段、展示预览、填写并报告结果。最终提交始终由用户完成。

资料本身与简历快照用途不同：网申可能需要简历未包含的结构化字段。须明确每个填写字段来自职业资料还是选定简历版本；冲突时由用户选择，不静默拼接或编造。

填写完成不等于真实投递。沿用 `applicationFact.ts` 和 ApplicationAttempt 合同：只记录填写或草稿；用户确认实际投递后通过既有写路径更新。网页成功提示识别只能作为辅助证据，不能凭字段写入成功制造 submittedAt。

### 技术选型与最终体验（2026-11-12 用户确认）

**以 [OpenJobAutofill](https://github.com/Br1an67/OpenJobAutofill) 为技术基础维护 Vocatrya 配套浏览器扩展，速申仅作为体验和站点适配参考。** 本决策取代此前“从零独立实现”的方向；不复用授权不明的速申代码或品牌素材。

上游参考提交为 `005eda98841b3671ead615ebfde5922f0dfd7c36`，本轮讨论中已静态查看源码、Manifest、资料样例和 [MIT 许可证](https://github.com/Br1an67/OpenJobAutofill/blob/005eda98841b3671ead615ebfde5922f0dfd7c36/LICENSE)。复用时保留版权和许可声明；实施时固定实际采用版本并核对依赖。现有适配代码、资料格式及本地规则可作为起点，不代表各站点或 Edge 已实测通过。

最终用户路径为：在「扩展工具 → 自动网申 → 设置与使用」安装插件、与 Vocatrya 配对、选择允许读取的资料，然后到招聘网页点击插件填写。Vocatrya 管理资料、版本及授权，浏览器插件负责页面识别和填写。资料变更后按需重新获取，减少两端重复维护。

手动导出/导入是**首阶段验证及长期备用方式**：Vocatrya 将选定非敏感资料转换为上游兼容格式，用户导入插件；资料更新后需重新导入。该方式导入后可在桌面应用关闭时填写，但不代表最终连接能力已完成。

连接式插件实时取资料时需要 Vocatrya 运行；应用未运行、连接撤销或副本过期须明确提示。缓存、离线填写及副本清除策略待实施时冻结，不静默用旧资料代替最新资料。主来源始终为 Vocatrya，插件保存的是带来源、版本和更新时间的受限副本，不自动反向覆盖职业资料。

上游可选 AI 用于字段识别，首阶段保留不配 AI 的本地规则路径。不会自动继承 Vocatrya 的 API 设置或账号登录；后续若复用应用 AI 服务，需单独实现受控调用，不将账号凭据复制到插件。网页 URL、标签、附近文本也可能含个人信息，仍需核对请求内容和脱敏，不把“不发送简历值”表述为绝对无个人信息外发。

### 实施与验收要点

- 将网站识别、字段映射、控件执行、结果校验分离；默认保留已有输入，歧义和低置信度交用户确认。
- 兼容框架受控输入，写后读取实际值；处理异步下拉、日期、动态表单与重复经历归属，不能只根据事件发送判成功。
- 提供预览、成功/缺资料/无选项/失败反馈；撤销只针对能安全还原的本次改动，不承诺撤销外部提交。
- 插件权限按需授予；证件、家庭成员、紧急联系人及附件独立授权，不同步整个数据库，不把凭据写进导出包。
- 首批使用合成资料及隔离浏览器配置验证；不得自动提交真实招聘申请。桌面连接交付时按授权验证 Windows Electron fresh-native 的配对、重开和记录回写。
- 网站改版需要持续维护；远程规则若后续采用，只接收受校验的声明式数据，不下载执行任意脚本。

## 3. EXT-NOTION：Notion 插件与 AI 操作

### 可行性与现状

**可以实现。** Notion 官方提供远程 MCP、OAuth 授权和内容读写工具，Vocatrya 可作为客户端接入。能力上限取决于实际发现的工具、账号权限、套餐及工作区策略，不等于可执行 Notion 界面的所有操作。

2026-11-12 基线的应用工具由 `src/lib/agent/tools/index.ts` 注册，并受 `src/lib/agent/agentRoles.ts` 白名单限制，当时尚未注册 Notion；本轮已集成 Notion 专用工具、角色过滤、批准和回执，真实远端合同仍待核对。现有向外提供的 Vocatrya MCP 服务与向外连接 Notion 的 MCP 客户端是不同方向；已有 SDK 依赖不代表接入完成。在当前聊天宿主安装 Notion 插件，也不会自动赋予 Vocatrya AI 相同能力。

### 接入方案

- **优先评估**：Notion 官方远程 MCP，地址 `https://mcp.notion.com/mcp`，使用 Streamable HTTP 和 OAuth。需实现客户端连接、授权回调、令牌安全保存/刷新/撤销、工具发现与受控执行；桌面回调按官方客户端指南确认注册要求及兼容性，不把“输入 URL”描述为已完成连接。
- **备选**：针对有限业务使用 Notion REST API + 内部连接令牌，用户显式授予目标页面访问权限。此路线要自己实现 API 工具封装；不是把 REST 令牌直接拿来代替官方远程 MCP 的 OAuth。是否交付双路线在实施时决定。
- 优先完成 Notion 专用适配，不默认建设允许任意地址、任意命令执行的通用插件市场。模型 BYOK 或账号登录方式本身不代表获得 Notion 权限。

### 目标体验与权限

设置中增加 Notion 连接区域，显示连接、授权工作区、可用能力及重连/断开。AI 可搜索和读取用户允许范围内的内容，并在用户审阅目标与内容后创建求职笔记、追加面试复盘、更新指定数据库记录。具体工具名及数据库/数据源 API 结构在实现时以官方版本和实际工具发现为准。

应用层为工具加前缀和显式白名单，避免名称冲突；有效能力为连接状态、账号权限、应用目标范围、角色白名单及运行时支持的交集。官方 OAuth 不应被假定天然只授权一个指定求职页面；如需限制在特定父页面/数据库，应由应用校验，并验证远程工具能否执行该限制。

2026-11-17 用户补充：首批优先招聘官网和就业岗位页面，必须识别页面状态与表单。识别目标包括岗位列表／详情、申请表、未登录、验证码、加载中、岗位失效／关闭及结果反馈；表单须识别字段标签、类型、必填、已有值、校验错误、动态重复经历和下一步／提交按钮。无法确认时报告未知及人工接管，不凭模型推测判成功；首批应以隔离样本核对这些行为。具体站点清单按可获得样本确定，状态／表单识别不等于已授权自动填写或提交。

### 邮件／日历的用户配置方式（2026-11-17 补充）

目标是用户连接自己日常使用的账号，继续在原软件查看邮件和日程，无需迁移到 Vocatrya 专属日历。连接入口展示服务、账号、授权范围、所选日历和默认写入目标，支持断开；邮件与日历分别授权，不因连接一项自动获得另一项权限。支持多服务的方向已登记，具体协议、交付顺序和实际支持范围在实施时验证，不宣称当前已接通。

| 用户常用软件／服务 | 建议接入方式 | 能力边界 |
| --- | --- | --- |
| Outlook／Microsoft 365 | 通过 Microsoft Graph 连接微软邮件和日历账号 | Outlook 客户端也能添加其他厂商账号；此类账号按实际供应商连接，不视为 Graph 可访问 |
| Gmail／Google Calendar | 分别使用 Gmail 和 Google Calendar 的授权 API | 用户选择连接邮件、日历或两者，不能把 Gmail 当作日历服务名 |
| Apple Calendar | 对 iCloud 日历评估 CalDAV 与应用专用密码等受支持方式；实施时核实认证方案 | Apple Calendar 是客户端；其中的 Google／微软日历连接原服务。本机独有、未同步日历不承诺 Windows 桌面可直接访问 |
| Notion Calendar | 优先连接用户在其中使用的 Google、Outlook 或 iCloud 底层日历账号 | 同一事件按供应商及远端标识去重；Notion 数据库日期通过既有 Notion 连接另行处理，不把 Notion MCP 当作所有日历事件的接口 |

截至本次核对，Notion 官方说明支持 Google、iCloud 和 Outlook 日历。上述底层账号接入是 Vocatrya 的实现建议，不代表已确认独立 Notion Calendar 公共事件 API。参考：[Microsoft Graph 邮件](https://learn.microsoft.com/en-us/graph/outlook-mail-concept-overview)、[微软日历](https://learn.microsoft.com/en-us/graph/outlook-calendar-concept-overview)、[Gmail API](https://developers.google.com/workspace/gmail/api/guides)、[Google Calendar API](https://developers.google.com/workspace/calendar/api/guides/overview)、[Apple 应用专用密码](https://support.apple.com/en-us/102654)、[Notion Calendar 账号兼容说明](https://www.notion.com/help/create-a-notion-calendar-account)。

Grill Me 借鉴持续追问的方法，针对求职重写，不直接复制开发工具中的指令和依赖。每轮围绕一个重点，允许跳过、暂停和查看阶段总结；压力面试由用户主动选择。面试追问作为现有 Agent 对话内的 Skill，不恢复已隐藏的独立面试练习板块，不撤销 EXT-INTERVIEW-WEB 的暂停安排。面试复盘复用既有职位／面试事件及复盘合同，不另建平行记录体系。
