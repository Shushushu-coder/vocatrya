## 1. 简历版本导航（UI-RC-RESUME-NAV）

【已确定】将“简历版本”从设置移到左侧主导航，使其成为容易发现的业务入口。

【建议】放在“我的职位”前面；概览里的快捷入口继续保留。

【待讨论 D1】侧边栏的准确位置，以及概览快捷入口是否保留。

验收检查点：侧边栏可直接进入简历版本；设置内原入口完成迁移；已有简历版本及其关联仍可访问。

## 2. 概览上半部分（UI-RC-OVERVIEW）

【已确定】保留“准备、行动、复盘”三个标题，添加浅色标签；介绍使用简短大白话，面向大众用户。功能入口在鼠标未悬浮时也应能看出可以点击。

【已确定】流程引导表达推荐而非要求，并在末尾使用 😄。用户提出的原文如下，后续润色尚未确认：

> 推荐按「准备 → 行动 → 复盘」组织求职：三个阶段随时可进入，不必按顺序完成。😄

【建议】介绍与入口设计：

| 项目 | 候选设计 |
| --- | --- |
| 准备 | 整理经历、准备简历，提前练好面试。 |
| 行动 | 记录投了哪些岗位，跟进面试和待办。 |
| 复盘 | 记下面试问答，看看下次怎么答得更好。 |
| 浅色标签 | 准备蓝色、行动绿色、复盘紫色；主体保持白色，颜色不作为唯一识别方式。 |
| 功能入口 | 使用浅底色或细边框、图标及右箭头，整行可点击；悬浮时加强反馈。 |
| 卡片高度 | 减少空白，使三个分组更紧凑。 |
| 新增操作 | “新增职位／新增待办”用加号，与查看入口区分。 |
| 咨询入口 | 可结合分组调整文案，但必须与真实进入的咨询语境一致。 |

【待讨论 D2】最终介绍、顶部标题、引导语是否润色、具体配色与入口样式；咨询入口是否调整。候选顶部标题“求职，从这里开始”和后续润色句“推荐按「准备 → 行动 → 复盘」安排求职，随时可以进入任何阶段，不必按顺序完成。😄”均未定稿，不替换上面的用户原文。

验收检查点：三个原标题保留；浅色标签清楚可辨；介绍通俗；无悬浮时可辨认入口且可实际进入对应功能；阶段可自由进入，不引入顺序门槛。

## 3. 我的职位拖动与置顶（UI-RC-JOB-ORDER）

【已确定】加入六点拖动手柄，支持用户将重要职位排到前面；同时加入置顶与取消置顶。

【建议】列表每行最左侧、卡片左上角显示手柄；列表与卡片共用顺序，自动保存，重新打开仍保留。行尾／卡片“⋯”菜单提供置顶操作，并以图钉标识置顶状态。

【建议】置顶职位优先展示；置顶区和普通区内均可拖动，跨区通过置顶／取消置顶操作。工具栏单独提供“排序”，与“全部职位”等筛选区分；自定义排序时显示手柄，日期排序时隐藏手柄。

【待讨论 D3】默认排序及选项、是否采纳上述跨区规则、取消置顶后的落点、筛选／搜索／分页下拖动的含义、新职位插入位置，以及是否增加上移／下移操作。持久化与视图共用规则需在实施前确认。

验收检查点：按冻结规则完成列表与卡片拖动、置顶及取消置顶；重新打开后顺序与置顶状态保持；拖动不误触职位详情；排序与筛选组合行为一致。保存失败应有明确反馈，不显示虚假的已保存状态。

## 4. 待办任务与面试题库分类区（UI-RC-TAG-LAYOUT）

【已确定】保留任务分类和技能标签区域，取消夹在主导航与内容之间的竖栏，移到内容卡片内部、标题及工具栏下方，采用常驻横向标签区；不改为折叠表单。两页使用统一视觉和筛选交互，分别保留“任务分类”“技能标签”的业务名称。

【建议】标签显示名称及数量，选中项用浅蓝底色、其余浅灰；与下方内容左右对齐，切换后保持标签区位置稳定。

【待讨论 D4】标签数量较多和长名称的处理。候选为默认两行，点击“查看全部标签”在原处铺开；长名称省略并提供完整名称提示。两行、展开方式、数量统计口径及单选／多选规则均未冻结，不将它们当成取消折叠表单的例外要求。

验收检查点：两页分类入口常驻且可筛选实际结果；选中态明确；标签较多、名称较长及窄窗口时内容可访问，主要列表不被挤压或遮挡；原有筛选功能保持可用。

## 5. 关于信息随版本更新（UI-RC-ABOUT）

【已确定】更新应用版本时，同步更新“设置 → 关于”中的版本号及相关版本信息，使其与实际运行版本一致，包括 RC 标识。

【建议】优先复用项目现有版本来源，减少手工同步遗漏。

【待讨论 D5】除版本号外哪些信息随版本变化（如更新说明、日期等），以及具体同步方式。此项不授权本轮升版、构建或发布。

验收检查点：关于页显示与实际目标产物一致的版本号和 RC 标识，其他版本信息按冻结范围同步，不残留旧版内容。

## 6. 左下角用户字母头像（UI-RC-AVATAR）

【已确定】将左下角代表用户的默认人形头像改为类似 ChatGPT 的昵称头像：**英文昵称取第一个字母并大写，中文昵称取第一个字**，不取多个字母、不把中文转换为拼音。

【建议】沿用现有头像容器，昵称更新后同步显示。

【待讨论 D6】空昵称、前导空格、数字或符号开头、混合昵称和特殊字符的取值／兜底规则，以及背景色；不擅自以邮箱代替昵称。

验收检查点：英文昵称如 `alice` 显示 `A`，中文昵称如 `小明` 显示 `小`；昵称变更后显示正确；异常昵称按冻结规则展示且不溢出。
